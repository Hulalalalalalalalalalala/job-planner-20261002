Install
python3 --version
Python 3.10 or newer; no third-party dependencies.

Start
python3 job_planner.py samples/plan.json
Reports completed 3 and failed 0; saves .results/latest.json.

Dependencies
python3 job_planner.py samples/plan-dependencies.json --output .results/deps.json
Reports completed 1, failed 1 and blocked 2 (exit 1): the failing branch blocks
its downstream chain while the independent CSV summary still succeeds; forward
references run in the earliest-ready plan order.

Partial runs
python3 job_planner.py samples/plan-dependencies.json --only joined-checksum
Runs only the named job plus its prerequisites; repeat --only to select several
targets. Unknown, blank or repeated names exit 2 with an error JSON.

Preview
python3 job_planner.py samples/plan-dependencies.json --preview --only joined-checksum
Prints the jobs that would run, in run order, with depends_on, reason
(target/prerequisite, or all without --only) and required_by; exits 0 and runs
nothing. The whole plan is still validated; failures exit 2 with an error JSON.

Retry preview
python3 job_planner.py samples/plan-dependencies.json --retry-preview .results/deps.json --output .results/deps.json
Reads the named report and prints {"targets": [...], "jobs": [...]}: targets are
the report's failed/blocked tasks in plan order and jobs cover them plus every
prerequisite (shared once), in run order, with the same fields as --preview.
Reports may be partial and report may equal --output. Empty results or no
failures print {"targets": [], "jobs": []}. Nothing runs or is written; a bad,
missing or escaping report path exits 2 with an error JSON. Cannot combine with
--preview or --only.

Retry
python3 job_planner.py samples/plan-dependencies.json --retry .results/deps.json --output .results/deps.json
Executes the same targets and scope the preview would show: failed/blocked
tasks plus every prerequisite (even ones that completed before, shared once);
unrecorded tasks join only when required and unrelated branches never run.
Ordering, failures and blocked_by follow a normal run, judged on this run's
results only. The report at --output holds just this run's records; report may
equal --output (targets use the pre-overwrite content). No targets prints
{"completed":0,"failed":0}, exits 0 and touches no files. Bad reports and
plans exit 2 with an error JSON; output write failures exit 2 without undoing
finished tasks. Cannot combine with --only, --preview or --retry-preview.

Compare
python3 job_planner.py samples/plan-dependencies.json --compare .results/deps.json .results/deps.json
Reads two reports without running anything and prints {"jobs": [...]}, one
entry per task recorded in either report in plan order, each with name,
before, after (null on the missing side; otherwise just status plus
result/error/blocked_by) and change: added, removed, changed or unchanged.
Status or payload differences count (including error text); result compares
as JSON (true is not 1, a number is not the same digits in a string,
object key order is ignored, array order matters) and numbers nested in
result compare by their exact decimal value without float precision loss
(1, 1.0 and 1e0 are equal, as are 1e400 and 10e399 and -0 and 0, while
0.10000000000000001 vs 0.1, 9007199254740992.0 vs 9007199254740993.0,
1e400 vs 2e400 and 1e-400 vs 0 differ); both sides keep the original
numeric value as a JSON number and blocked_by compares as a set and
prints in current dependency order. Both paths may be the same file.
A valid comparison exits 0 even with failed records; bad reports/
payloads, escaping paths or a bad plan exit 2 with an error JSON —
NaN, Infinity and -Infinity reject a report even in ignored extra
fields, though long decimals and legal exponents beyond float range are
fine. Nothing is created or written. Cannot combine with --only,
--preview, --retry-preview or --retry.

Explain
python3 job_planner.py samples/plan-dependencies.json --explain .results/deps.json --output .results/deps.json
Reads one report without running anything and prints {"jobs": [...]}, one
entry per failed/blocked task in plan order, each with name, status and
causes. A failed task's cause is itself with its error string; a blocked
task follows the report's blocked_by chains to terminal failed tasks or to
unrecorded tasks ({"status": "unrecorded", "error": null}), deduplicated by
name and ordered by the plan. Nothing is inferred from current files or
other declared dependencies; a blocked_by chain reaching a completed record
exits 2 with an error JSON. Partial reports are valid and unrecorded tasks
appear only as trace endpoints; no failures print {"jobs": []}. Report
validation, paths and output protection match --compare; report may equal
--output. A valid explanation exits 0 even with failed records; bad
reports, escaping paths or a bad plan exit 2 with an error JSON. Nothing is
read besides the plan and report and nothing is created or written. Cannot
combine with --only, --preview, --retry-preview, --retry or --compare.

Change preview
python3 job_planner.py samples/plan-dependencies.json --changed samples/notes.txt
Prints {"targets": [...], "jobs": [...]} for the tasks whose resolved input
path changed plus every downstream dependent (targets, in plan order) and
those targets plus all prerequisites (jobs, in run order, with the --preview
fields plus triggered_by: the directly changed tasks reaching each job, or
[] for prerequisite-only jobs). Repeat --changed for more paths; paths
resolve like plan inputs (absolute or escaping paths exit 2), need not
exist and are never read, and duplicates or argument order change nothing.
No match prints {"targets": [], "jobs": []} and still exits 0. The whole
plan is validated first; failures exit 2 with an error JSON. Nothing runs
or is written. Cannot combine with --only, --preview, --retry-preview,
--retry, --compare, --explain or --history.

Smoke Test
python3 -B -m unittest -v
Checks real file operations, recorded errors, directory boundaries, symlinks,
dependency validation/blocking, plan and retry previews, manual retries,
report comparison, failure explanation and the CLI.
